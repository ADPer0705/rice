# OpenCode

OpenCode's configuration is small and entirely file-based, so it is versioned
here. Sessions, history and API credentials are deliberately **not** captured.

## What is captured

| Path | Notes |
| --- | --- |
| `home/.config/opencode/opencode.json` | MCP servers; the outpost token is a `{file:…}` reference, never inline |
| `home/.config/opencode/opencode.jsonc` | openwiki MCP |
| `home/.config/opencode/skills/` | installed skills (`openwiki`) |
| `home/.local/state/opencode/model.json` | recent/favourite models and variants |

The **whole** `~/.config/opencode` directory is captured, so agents, commands,
plugins and `AGENTS.md` added later are picked up without editing
`scripts/lib/manifest.sh`.

Not captured, on purpose:

| Path | Why |
| --- | --- |
| `~/.local/share/opencode/opencode.db` | sessions, messages (66 sessions / ~8.5k messages), plus provider credentials |
| `~/.local/share/opencode/snapshot/` | file-edit undo history (~78 MB) |
| `~/.local/share/opencode/{log,tool-output,shell}` | logs and caches |
| `~/.config/opencode/service.json` | runtime service password, regenerated by the server |
| `~/.opencode/bin`, `~/.cache/opencode` | binaries, reinstallable |

Restoring the config gets a working install; chat history is not recoverable by
design.

## Secrets

Only one config-embedded secret exists: the outpost MCP bearer token.
Provider keys (DeepSeek, Mistral, OpenCode Console) live in OpenCode's
credential store and are managed by `opencode auth`; they are never part of
this repo or the bundle.

The token is stored as a file and referenced from config:

```jsonc
"headers": { "Authorization": "Bearer {file:~/.secrets/outpost.token}" }
```

```
/mnt/s/.adper/opencode/outpost.token   # authoritative copy (owner-only)
~/.secrets -> /mnt/s/.adper/opencode   # stable path used by the config
```

Rules:

- **No trailing newline.** `{file:…}` substitutes raw bytes; a stray `\n` makes
  an invalid HTTP header. Write it with `printf '%s'`, not `echo`.
- **A missing file resolves to an empty string**, not an error, so the header
  becomes `Bearer ` and outpost answers 401. `bash bin/rice doctor` checks for
  this.
- **Rotate with** `opencode reload` (or restart the service); the file is read
  at config load.
- `/mnt/s` is mounted `umask=077`, so everything there is owner-only. If the
  mount options regress to `umask=022`, the token becomes world-readable.
- `~/.secrets` must resolve before OpenCode starts. If `/mnt/s` fails to mount,
  outpost silently loses its token — `rice doctor` is the fastest way to see it.

## Backup commands

```bash
bash bin/rice sync      # capture -> commit -> push (daily timer)
bash bin/rice backup    # build + publish opencode-config-<date> release
```

`backup` builds a ~8 KB `opencode-config-<date>.tar.zst` containing `config/`,
`state/model.json`, a `MANIFEST` (opencode version, rice commit, per-file
sha256) and `restore.sh`. It:

- refuses to publish if the bundle contains anything credential-shaped
  (`Bearer …`, `sk-…`, `ghp_…`, `AKIA…`, PEM keys, `outpost.…`);
- skips publishing when the content hash is unchanged (use `--force`);
- keeps the last 10 releases and the last 5 local archives in
  `~/.local/state/rice/opencode-backup/`;
- `--verify` re-extracts the archive and checks it against its `MANIFEST`.

Releases live on this same repo: `ADPer0705/rice`, tag `opencode-config-<date>`.

## Fresh machine

```bash
git clone git@github.com:ADPer0705/rice.git
cd rice
bash bin/rice deploy                  # writes ~/.config/opencode (+ backs up existing)

mkdir -p ~/.secrets
printf '%s' '<outpost-token>' > ~/.secrets/outpost.token   # no newline
opencode upgrade                      # match MANIFEST's opencode version
opencode auth login                   # DeepSeek / Mistral / OpenCode Console
opencode mcp list                     # openwiki, playwright, outpost -> connected
```

Without the repo, use the release bundle instead:

```bash
gh release download opencode-config-<date> -R ADPer0705/rice --pattern '*.tar.zst*'
sha256sum -c *.sha256
tar -xf opencode-config-<date>.tar.zst
bash opencode-config/restore.sh
```

`restore.sh` copies the config into place and prints the token step if
`~/.secrets/outpost.token` is missing.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| `outpost` fails with `ECONNREFUSED` | the outpost service is not running on `127.0.0.1:8090`; unrelated to the token |
| `outpost` fails with 401 | token file missing/empty or stale — check `wc -c ~/.secrets/outpost.token`, then `opencode reload` |
| `outpost` sends `Bearer ` | `/mnt/s` not mounted, so `{file:…}` resolved to an empty string |
| `rice status` says the opencode dir drifted | live config changed; run `bash bin/rice sync` |
